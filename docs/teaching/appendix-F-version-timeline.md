## 第一次迭代：v2 MMFF — 初探阶段

**时间**：2026-04-03 ~ 04-04

**目标**：先建立一条能跑通的对接 pipeline，**验证 Kuo2024 在 Gpr2/Gpr3 上的 WT 亲和力排名是否可复现**。这一轮还没有"预测新突变"的野心——先把数据流从 PDB 到 ΔG 打通。

**做了什么**：受体从 AlphaFold DB 下载 → OpenBabel 加氢 → 配体从 PubChem 下载 SDF → RDKit MMFF 几何优化 → Meeko 转 PDBQT → Vina 单受体单配体对接（box spacing = 0.25 Å，exh = 200）。

**得到了什么**：04-04 一轮 production run（约 8 小时）完成，9 组 ΔG 数值全部落在 Kuo2024 报告区间内——**定性排名验证通过**。

**这一轮没意识到的偏差**：没有 Hu2024 作为阳性对照时，pipeline 里所有的系统偏差都是"未知的未知"。下一轮的触发正是"想用 Hu2024 做一次绝对数值对标"这个动作。

## 第二次迭代：docking-repro v1 — 发现配体几何偏差

**时间**：2026-04-05 ~ 04-06

**触发**：用 v2 得到的 GprC × ascr18 ΔG 去对标 Hu2024 报告值（−8.29 kcal/mol），数值差距远超一轮 seed 噪声。如果想把 Hu2024 当阳性对照用，必须先精确对齐 Hu2024 的协议。

**这一轮的三个关键决策**：
- **切换配体几何来源**：RDKit MMFF → Orca B3LYP/def2-TZVP DFT 优化（Hu2024 明文协议）
- **切换受体准备工具**：OpenBabel → ADFR Suite（Hu2024 明文协议，与 Vina 同团队接口稳定）
- **采用两阶段对接**：先 coarse（box = 40 Å）后 refine（box = 10 Å），以为这是 Hu2024 的做法

**发现的偏差**：
- MMFF 优化出的配体几何与 DFT 几何在 ΔG 上有 ±0.5 kcal/mol 量级的可观偏差。这一条直接推翻了 v2 阶段所有带 MMFF 配体的数值结果——不能作为对接结论的依据
- 再仔细读一遍 Hu2024 正文发现**原文就是单阶段对接**，"两阶段"是本轮对文献协议的第一个认读错误

**本轮教训**：在做方法选择辩护前，先把文献协议的原文逐条拆开读清楚；任何参数都不能凭直觉推断。这条教训直接推动了 repro v2 阶段对"每个参数都要有出处"的要求。

## 第三次迭代：docking-repro v2 — 修复四大系统偏差

**时间**：2026-04-07 ~ 04-10

**触发**：v1 切到单阶段对接后重跑 GprC × ascr18，得到 ΔG = −5.41 kcal/mol，与 Hu2024 的 −8.29 差 2.88 kcal/mol——这不是 seed 噪声能解释的差距，pipeline 里一定还有系统性问题。这一轮从"协议对齐"升级到"根因定位 + 方法重构"。

这一轮修正的四个偏差彼此独立，任何一个不修都不能通过 WT 协议级对齐：

**① GprC grid box 偏移 18.1 Å**
- **现象**：GprC grid center 落在 ICL3 环区，不在 TM 螺旋腔内
- **根因**：v2 脚本用"全蛋白质心"算 box 中心，GprC 的长 ICL3 环把质心拉偏了
- **修正**：改用 annotation-based TM 域提取（UniProt TM 注释 + DeepTMHMM 交叉验证拿到 TM 螺旋区间），只用 TM 螺旋原子计算质心
- **验证**：修复后 GprC 的结合腔重新进入 box，ΔG 从 −5.41 改善到 −8.235（Δ = 0.05 vs Hu2024）

**② ascr18 PDBQT 从 26 原子被截断为 15 原子**
- **现象**：ADFR 准备出的 ascr18 PDBQT 只有 15 个原子，应有的 26 个里末端羧基尾完全丢失
- **根因**：`src/modeling/docking-repro/prepare_ligand.py` 里自实现的 `freeze_terminal_torsions()` 函数**删掉了 ATOM/HETATM 行**而不是只移除 BRANCH/ENDBRANCH 标记——这是我们自己代码的 bug，不是 ADFR 或 Meeko 的默认行为
- **发现过程**：排查 IFP 阳性对照 MISS 时顺藤摸到 PDBQT 原子数异常，不是主动审计
- **修正**：保留 ATOM/HETATM，只移除 BRANCH/ENDBRANCH；新增 `fix_ascr18.py` 从 Orca 优化过的 PDB 重生 PDBQT

**③ BW → 序列号映射错位**
- **现象**：早期 Gpr3 的一批 alanine scan 扫了 PLIP 推荐的残基，ΔΔG_sel 全部落噪声区；IFP 交叉验证后发现这些残基根本不在配体接触面上
- **根因**：BW 编号到受体序列号的映射依赖算术（锚点 + BW 算术），GprC 上早期一度把 N2.57 错标到 N56 而不是 N60
- **修正**：从 GprC D2.50 = ASP53 锚点出发（TM2 范围内唯一酸性残基）重新推导 → N2.57 = ASN60 / N2.53 = ASN56 / S2.41 = SER44。三个位置的氨基酸类型都与 Hu2024 strain 命名一致（三处独立匹配概率 ≈ 1.25 × 10⁻⁴）
- **依据**：推导链见 `docs/logs/2026-04-07.md:319-324`；独立追溯审计见 `docs/logs/truth-audits/2026-04-12_0205.md` 后记 A

**④ v2 PLIP Gpr3 残基全部无效**
- **现象**：v2 用 PLIP 从 Gpr3 WT pose 里提取的 8 个高频接触残基，拿去做 alanine scan 后全部落噪声区
- **根因**：PLIP 对本地 PDB 的处理有条件失效；同一份 pose 在 ProLIF 里得到的高频残基完全不同
- **修正**：切换 IFP 工具从 PLIP 到 ProLIF；重新跑 Gpr3 scan_residues（PLIP 的 8 个残基全部替换为 ProLIF 的 8 个）。正是这次切换让 I141A（后来的 Tier 1 候选，ΔΔG_sel = −0.786）被发现
- **触发**：04-08 一次 Truth Audit 发现 v2 PLIP 结果可信度为零

**本轮验证依据**（2026-04-12 修正后的口径）：

| 证据层 | 内容 | 作用 |
|---|---|---|
| WT 协议级复现 | GprC × ascr18 ΔG = −8.235 vs Hu2024 报告值 −8.29，Δ = 0.05 kcal/mol | 证明 WT 绝对数值可对齐 Hu2024 协议 |
| Hu2024 loss-of-function 对照 | 三个阳性对照（N60A / R395A / S44A）全部落 Tier 4，方向一致 | 证明 pipeline 能识别"会坏"的突变方向 |
| 本轮 pipeline 的已知边界 | Hu2024 阴性对照 N56A 也落 Tier 4（假阳性） | 证明 GprC alanine scan 对残基特异性缺乏分辨力 → Top 6 工程推荐全部来自 Gpr2/Gpr3 |

对照分层的完整叙事（包括 N56A 为什么是阴性对照、为什么仍然把边界披露本身作为可信度证据）见 Lesson 4。这里只记"本轮 pipeline 被什么证据支撑、又被什么证据限定"。

## 从三次迭代里读到什么

读这条时间线时不要只看"我们最后得到了什么"，而要看**每一步是被什么对照/数据拆穿的**：

- **v2** 没有绝对对照，所以偏差都是"未知的未知"——你只能判断定性排名是否合理，不能判断数值是否可信
- **v1** 引入 Hu2024 做绝对数值对齐，一下暴露了两条问题：MMFF 配体几何偏差 + 协议认读错误
- **v2（docking-repro）** 在 v1 的基础上做 WT 数值复现 + 对照对齐，又暴露了四个独立的系统偏差

**每一次迭代的驱动力都是"把阳性对照跑出正确结果"，不是"让方法更复杂"**。这一点是组员讲迭代故事时最值得主动说出的姿态：pipeline 的每一层决策都不是拍脑袋，而是被文献阳性对照逼出来的。这也是干实验方法学诚信的具体展开方式——**对照是外部检验，不是装饰**。
