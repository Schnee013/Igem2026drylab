## 读者画像

- 3-4 名大二学生，生物学背景
- **不是局外人**：作为核心成员参与了整个 iGEM 项目的方案设计（受体选择、配体逻辑、双通道比值型设计等），一直跟着湿实验组
- **真正欠缺的是**：干实验侧的技术和知识——工具怎么用、pipeline 怎么跑、数字怎么解读、答辩怎么讲
- 他们知道"为什么选 Gpr2/3/GprC"和"为什么 ascr#18 vs ascr#3"，但不知道"Vina 是什么""PDBQT 是什么""ΔΔG_sel 怎么算出来的"
- **量化基础**：懂生物学定性概念（Kd、亲和力、选择性），但不懂 ΔG/Kd 换算、kcal/mol 的物理含义 → KNOW 轨需要从定性搭桥到定量
- **计算机基础**：几乎为零。不知道终端是什么、没用过命令行、不知道 cd/ls 等基础命令。部分学员使用 Windows 系统。
- **IDE/工具**：未接触过 VS Code 或任何代码编辑器。需要从 VS Code 安装 + Copilot 设置开始教。

## 真实目标（按优先级）

1. **能独立贡献干实验工作**（不再只有用户一个人做）— 最重要
2. **能在巴黎答辩现场回答评委细节提问** — 理解推理链，不是背答案
3. 以 docking 项目为教学载体，建立计算生物学基础能力

## 时间与交付方式

- 2-3 周（可延长）
- 介于自学和带教之间：文档需要自包含、可反复查阅；用户在组会上答疑和带关键操作
- 不做课堂笔记（怕记错），文档本身是可靠学习材料
- DO 轨要求逐命令可复制 + 预期输出（GROMACS tutorial 风格）

## 当前材料（v1）的三个结构性问题

### 问题 1：起点定错了 — 把读者当成了项目局外人
- Lesson 1 花 130 行重新讲项目定位、受体选择、配体逻辑 — 这些他们参与设计过
- 真正需要从零讲的是"干实验部分"：工具、方法、数字的含义
- 冗余内容占总量约 30-40%

### 问题 2：动手太晚 — 理论全部前置，操作排在最后
- 当前顺序：L1 定位 → L2 方法 → L3 代码 → L4 统计 → L5 结果 → L6 迭代 → L7 动手
- "你能做什么"排在第 7 课，学生要读完 ~2 万字理论才第一次跑出一个数字
- 违反技能习得的基本规律（先做再懂为什么）

### 问题 3：答辩知识和操作技能混在一起
- 每一课同时试图教"怎么操作"和"怎么讲"
- 想查操作步骤要在叙事里翻找，想复习答辩要跳过代码细节
- 两种技能的学习方式完全不同（操作靠跟做，答辩靠练讲）
