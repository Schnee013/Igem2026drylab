# 每文档讲解要点（讲课笔记）
> **用途**：组会上补充学习者文档之外的上下文。每份文档 3-5 条"如果成员问这个，你应该这样展开"。
>
> **不复制文档内容**——只给你自己的提示和指针。
>
> **v2 文件位置**：`docs/teaching/v2/`

## KNOW-1：你算出了什么
**成员可能问**：为什么不直接做别的受体，非要在 Gpr2/3/GprC 上？
→ 核心逻辑：没有文献基线的受体没法做阳性对照验证。Hu2024 提供了 Gpr2/3/GprC 的 WT 亲和力数据 + 功能残基（N60A/R395A/S44A），**只有这三个受体能做阳性对照**。展开时引 KNOW-2 §4（对照验证）和 KNOW-2 §6（迭代故事——正是因为 v2 阶段没有对照才没发现四个偏差）。注意：KNOW-1 §4 讲的是方法链（工具选择），不是受体选择。

**成员可能问**：ΔΔG_sel 的公式看不懂。
→ 不要从数学切入。从工程目标切入："你要的是传感器区分两个信号的能力，不是结合力。ΔΔG_sel 就是在量这个区分能力"。KNOW-1 §2 的反例（亲和力增强但选择性不变）比公式更有效。

**容易漏的点**：成员读完 KNOW-1 可能只记住"Top 6 是什么"，忘了"Top 6 是快照不是终点"。组会上主动问一句"Top 6 会不会变？"——如果答"不会"就需要纠正。

## KNOW-2：为什么值得信
**成员可能问**：3σ 和 2σ 的区别是什么？
→ KNOW-2 §2 有完整论证。更直觉的版本："2σ 的假阳性率约 5%，90 条扫描里会有 4-5 条假信号混进来——比真信号还多。3σ 把假阳性率压到 0.3%，90 条里可能只有 0-1 条假信号"。

**成员可能问**：N56A 为什么是假阳性？
→ KNOW-2 §4 是权威讲解点。核心是"Hu2024 原文说 N56 突变无功能影响（具体 figure/table 号待查原文确认），所以它的 |ΔΔG_sel| 应在噪声内，但实际大幅偏移（+1.139 = 7.2σ）"。追问"为什么假阳性"时答"GprC alanine scan 整体缺乏残基分辨力——14 个位点 13 个 |ΔΔG_sel| > 2σ"。

**成员可能问**：绝对精度 vs 相对精度听不懂。
→ 用类比："体重秤每次都偏重 2 公斤（绝对偏差），但你今天和昨天的差值是准的（相对精度）。我们只用差值排名，不用绝对数字"。

**§8 双通道比值型分析**：成员可能问"Channel B 候选和 Top 6 一样可信吗"→ 不一样，Channel B 没有独立阳性对照验证，只有噪声阈值筛选。另一个好问题："V138R 和 V138T 怎么方向相反"→ 同一位点不同替换改变侧链性质（Arg 大而带正电 vs Thr 小而极性），影响对两个配体的差异选择性。

**这是被追问最密集的文档**。组会上在这一课花的时间应该最长。

## KNOW-3：诚实边界
**成员可能问**：V138R 如果不是盐桥那到底是什么？
→ 目前只能说"空间富集"——ARG138 的长侧链在 ascr18 附近出现得比 ascr3 附近多。**到底是什么相互作用**在等 MD 回答。如果成员追问"那我们怎么知道它真的好"——答案是"ΔΔG_sel = −1.07 这个数值是 pipeline 里最强的信号，统计上远超 3σ。机制解释不确定不影响数值排名的可信度"。

**H4 验收的关键文档**：组会上专门花 5 分钟让每个成员对着你讲一遍"V138R 到底观察到了什么、没观察到什么"。如果有人说"形成了盐桥"→ 当场纠正。

**成员可能问**：局限性这么多，pipeline 还有用吗？
→ 这是最好的教学时刻。"有用和完美是两件事。pipeline 在 Gpr2/Gpr3 的 Channel A/B 识别上有三条独立证据支撑（WT 复现 / 阳性对照 / 机制自洽），这比大多数 iGEM 干实验更扎实。但我们同时知道它在 GprC 上有假阳性、在 V138R 上有未实证的机制——这两条边界不是弱点，是方法学诚信的展示"。

**容易漏的点**：成员可能只记住"不能说 4/4 通过"但不理解为什么。确保他们能讲出"N56A 是阴性对照，它应该不受影响但 |ΔΔG_sel| 显著偏移"这条因果链。

## KNOW-4：答辩准备
**不需要在组会上专门讲**——成员读完自行用 qa-bank 自测。组会上只需执行红队演练（见 `red-team-drill.md`）。

## DO-1：首次对接
**成员可能问**：config.yaml 为什么这么重要？
→ 单一权威源原则。展开时可以举一个反面例子："如果路径散在 5 个脚本里，你改了一个忘了其他四个，对接用的受体和 IFP 分析用的受体就不是同一份——这个 bug 你可能永远发现不了"。

**注意**：PDBQT 数据文件不在 git 里，成员需要单独获取（DO-1 §2 有说明）。组会前确认数据已分享。

## DO-2：突变体全流程
**成员可能问**：BW 编号太难了，怎么记？
→ 不需要记所有映射。只需要记一条：**GprC D2.50 = ASP53 是锚点**，其他位置从这个锚点加减偏移。组会上可以在白板上画一条 TM2 螺旋，标出 ASP53，然后从 53 开始数 +7 = ASN60（N2.57），让成员亲手数一遍。

**成员可能问**：AF3 预测的结构可信吗？
→ 引导到 KNOW-2 §5 的三层防御。关键：只在 TM 内 pLDDT >90 的区域做扫描。

## DO-3：可视化
**成员可能问**：IFP 接触频率高就是好吗？
→ KNOW-3 §2 的关键警告：接触频率 ≠ 结合贡献。展开："一个残基可能接触 20 次但每次几何都很差（刚好碰到距离阈值），另一个只接触 3 次但每次都是完美的氢键几何"。

## DO-4：如何贡献
**不需要在组会上专门讲**——成员自己读完就能认领任务。组会上只需要确认"每个人选了什么任务、第一步是什么"。

**如果成员选不出来**：建议从"PyMOL 渲染"开始——门槛最低、产出最直观、对 PI 最有价值。

## 方法辩护补充（跨文档）
**成员可能问**：为什么不直接用 FEP 精度更高？
→ KNOW-1 §4 + KNOW-2 §7 的三重约束（协议一致性 / 授权 / 规模）。但更深的一层是：**FEP 即使用了，也没有 Hu2024 做对照**——这一条比"贵"更致命。

**成员可能问**：seed=42 为什么选 42？
→ **红线提醒**：不能说来自 Hu2024。正确答案是"任何固定值都行，关键是固定"。42 是程序员惯例（Hitchhiker's Guide），没有物理意义。

**成员可能问**：故事二（ascr18 截断）为什么不是主动发现的？
→ **必须诚实讲**：是被 IFP 阳性对照 MISS 逼出来的连锁排查。但这不丢人——"被另一路验证失败触发发现"恰恰说明 pipeline 里有多条独立的验证通道在互相兜底。qa-bank Q16 有精确叙事。

**成员可能问**：为什么不说"4/4 通过验证"了？
→ KNOW-2 §4 是权威讲解点。简短版："因为 N56A 是阴性对照不是阳性对照——我们之前把它的角色搞混了。truth audit 抓出来的"。
