# 硬门槛验收清单
> **用途**：判断成员是否准备好上答辩台的硬性标准。4 项硬门槛全部通过才签字；3 项软门槛是加分项。
>
> **本文件只管判断标准**，不管教学内容——内容在 `docs/teaching/v2/` 的 DO/KNOW 文档和 qa-bank 里。
## 硬门槛（4 项，全部通过 = 可上答辩台）
### H1：题库抽考
**做法**：从 qa-bank 43 题里随机抽 10 题，每题 90 秒。
**通过标准**：≥ 8 题答到核心论据（qa-bank 里 ✅ 标注的要点）。
**判断规则**：
- 论据到了但数字有小偏差（比如说 0.05 说成 0.06）→ 算通过
- 论据方向对了但缺了关键的一层（比如只说"Vina 精度不影响"但没说"因为系统偏差在差值里抵消"）→ 不算通过
- 说了 ❌ 里的任何一条 → 该题不通过，不管其他部分答得多好
### H2：60 秒电梯陈述
**做法**：不看任何材料，从零开始讲。严格 60 秒计时。
**通过标准**：5 要素全部出现（问题定位 / novelty / 方法+可信度 / 结果 / 局限+下一步）。
**判断规则**：
- 5 要素全到，顺序自然，数据准确 → 通过
- 5 要素全到但像背诵 → 通过（背诵比讲不出来好，自然度后面练）
- 缺了任何 1 个要素 → 不通过
- 特别注意：**局限+下一步**（V138R + MD）不能省——这是诚信叙事的锚点
### H3：三次迭代故事复述
**做法**：让成员讲"pipeline 迭代了几次，每次修了什么"。不限时间，但看流畅度。
**通过标准**：能讲出 v2 → repro v1 → repro v2 三个阶段，每个阶段至少一条"修正了什么"，至少一次的根因+修复。
**判断规则**：
- 能讲出三个阶段名 + 每个的关键变更 → 通过
- 能额外讲出"每次迭代是被什么对照拆穿的" → 优秀
- 只记得 repro v2 的四大修复但讲不出 v2 MMFF 和 repro v1 → 不通过（说明没理解迭代逻辑，只记了最后一轮）
### H4：V138R 盐桥诚实展示
**做法**：问"V138R 的盐桥你怎么看？"——看成员是主动承认局限还是被追问才承认。
**通过标准**：主动说出"目前只观察到空间富集（9 次 VdWContact），不能说盐桥形成"+ "这驱动了 MD 方向"。
**判断规则**：
- **主动**说出局限 + MD 承接 → 通过
- 被追问后才说"其实不确定" → 不通过（答辩现场不会有人帮你追问出诚实的回答）
- 说"V138R 形成了盐桥" → 严重不通过（这是事实错误）
## 软门槛（3 项，加分但不阻止上台）
### S1：能独立在 Mac 上跑 WT 对接
**做法**：让成员按 DO-1 自己操作 Mac，从 `conda activate docking` 到看到 JSON 结果。
**判断**：全程不问你，能自己跑完 → 通过。中间问了但最终跑通 → 半通过。跑不通 → 不通过。
### S2：能独立用 PyMOL 打开 Top 6 可视化
**做法**：让成员自己在 PyMOL 里加载一对 WT + mutant，做 align + matrix_copy，应用样式脚本。
**判断**：能看到正确的叠合画面 → 通过。忘了 matrix_copy 但知道问题在哪 → 半通过。
### S3：能自主认领至少 1 个接手任务
**做法**：问"你想做什么？"——看成员能不能从 DO-4 的四条路径里选一条，并说出第一步是什么。
**判断**：能选一条 + 说出具体第一步 → 通过。说"我还不确定"→ 不通过（但不阻止上台）。
## 使用方式
- 验收不需要一次做完——可以分几次组会逐项检查
- H1-H4 全部通过后在飞书记录"日期 + 成员姓名 + 通过"
- 如果某项多次不通过，回去看对应 v2 文档（DO/KNOW）重新学习后再测
