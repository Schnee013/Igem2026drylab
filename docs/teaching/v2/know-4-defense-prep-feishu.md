## 1. 60 秒电梯陈述模板
在 iGEM 答辩现场，评委可能直接问"你们 docking 做了什么"——你需要在 60 秒内讲清楚。
**5 要素框架**：
1. **问题定位（10s）**：我们需要改造 GPCR 受体，让它对 ascr#18 / ascr#3 比值的选择性增强
2. **方法（15s）**：用 Vina 对接做 122 条突变扫描（先广后深：32 alanine + 90 饱和），协议对齐 Hu2024 做阳性对照
3. **可信度（10s）**：5-seed 方差 + 3σ 阈值 + 三个阳性对照方向一致
4. **结果（15s）**：Channel A 14 条 + Channel B 11 条（无 caveat），配对 Top 3 已交接湿实验
5. **局限 + 下一步（10s）**：V138R 机制待 MD 实证，GprC 有已知假阳性边界

## 3. 组会红队演练流程
我会在组会上扮演 iGEM 评委，从题库抽题追问：
1. **第一轮（热身）**：每人抽 2 题基础题（Q1/Q2 级别），限时 90 秒
2. **第二轮（压力测试）**：抽 Q3-Q5 的追问级题目，我会故意追问"凭什么""如果不是呢"
3. **第三轮（红队）**：我会用 `_instructor/red-team-drill.md` 里的陷阱题
**卡壳时的三段式兜底**：
1. 先说你确定知道的部分
2. 再说你不确定但可以推理的部分
3. 最后说"这个问题的精确答案我需要查阅具体数据，但方向是……"
**绝对不能做的**：编答案。说"我不确定"远好于说一个错误的数字。
### DBTL 兜底姿态
遇到任何"如果你们的预测全错了怎么办"类质疑时，用 iGEM 工程循环框架回应：
**DBTL = Design → Build → Test → Learn**
- 干实验 docking = Design 阶段的预测工具（缩小搜索空间，不是给最终答案）
- 湿实验验证 = Test 阶段
- 预测被推翻 ≠ 失败 = Learn 阶段的高价值数据（告诉我们哪一层假设错了）
**万能姿态**：
> "全错不代表方法没意义。DBTL 循环本来就是让我们根据反馈迭代的。而且我们有多层证据链——3σ 统计阈值 + 三个 Hu2024 阳性对照方向一致 + 两种独立机制路径——全错的概率在统计意义上很低。更可能的情况是 Top 6 里有 2-3 条通过湿实验验证。"
这个姿态的核心是：承认预测的局限性，但强调方法学的价值和证据的多层性。
