## GPR MD 体系数量与采样队列决策

- 本轮讨论的问题是：如果把 `Gpr2/Gpr3 WT x ASCR3/ASCR18` 全矩阵都做，会形成 4 个 WT holo system、12 个 reps；如果再把 Channel A/B 前三位候选都纳入，并且每个候选各跑对应 ligand system，则约为 6 个 mutant systems、18 个 reps。两者合计会接近 30 个 200 ns 级 replicate，按当前 E2 共享 A100 条件不可作为默认启动队列。
- 讨论的第一个问题是能否只取每个 channel 的首位候选。结论是可以，且应当作为当前默认路线：`Gpr2_R59C` 和 `Gpr3_R167Y` 已是 refreshed docking handoff 的首选双通道组合，Decision 005 也要求 mutant GPR 不直接进入 full-production 全量队列，而是先完成 input gate、短程 benchmark 和 staged production decision。
- 第二个问题是 benchmark 是否只做两个体系。结论是可以，但第一轮两个体系应优先使用 matched channel ligand：`Gpr2_R59C + ASCR18` 代表 Channel A/ascr18 偏好端，`Gpr3_R167Y + ASCR3` 代表 Channel B/ascr3 偏好端。`Gpr2 + ASCR3` 或 `Gpr3 + ASCR18` 这类反配体系更适合作为后续选择性对照，不应替代第一轮 candidate stability benchmark；只做两个 Gpr2 突变体也会削弱双通道设计本身的证据结构。
- 第三个问题是如果每个体系的 rep1 表现稳定，是否暂停 rep2/3。结论是可以，且推荐按 triage/funnel 使用 rep1：rep1 用于 package sanity、trajectory sanity、ligand pose stability 和初步 contact/lifetime 读出；rep1 不能写成最终统计稳定性结论。rep2/3 暂缓到 wet-lab、Gpr2/Gpr3 matched analysis 或最终 candidate selection 之后，只对被保留的最终体系补齐。
- 最终执行决策：不按 full matrix 或 top3 candidate 全量展开。当前优先队列改为：先等待 `Gpr2_WT + ASCR18` production rep1 完成并归档；随后推进 `Gpr2_R59C + ASCR18` 的 final coordinate/topology/index/warning gate，若通过则执行 smoke/benchmark -> 200 ns rep1；然后先做 `Gpr2_WT + ASCR18` 与 `Gpr2_R59C + ASCR18` 的 matched 分析比对。Gpr2 线形成 WT/mut 初步结论后，再启动 Gpr3 线的两个 matched ASCR3 system：`Gpr3_WT + ASCR3` 和 `Gpr3_R167Y + ASCR3`，同样先走 package gate、smoke/benchmark 和 rep1 triage，不默认启动 rep2/3。
- 该队列的解释边界：它是省算力的 staged evidence plan，不是宣称其他 top3 候选无效。若 `Gpr2_R59C` 或 `Gpr3_R167Y` 的 rep1 出现明显 ligand drift、package/energy sanity 问题或关键 contact 读出不支持原始设计，再回到 backup candidates 或反配控制；若 rep1 稳定，也只说明进入下一轮优先级，不直接替代 3-rep 统计结论。
