### [1] 无中生有 — WT 基线隐含假设

> （上下文推断）#5 可以直接运行 `run_mutagenesis_alanine.py`

- **问题**：`wt_singlestage/docking_results.json` 仅有 3 个 ascr18 条目（GprC_ascr18=-8.235, Gpr2_ascr18=-6.774, Gpr3_ascr18=-5.755）。`run_mutagenesis_alanine.py:load_wt_baseline()` 第 57-68 行显式校验 `GprC_ascr3`、`Gpr2_ascr3`、`Gpr3_ascr3` 键的存在，缺失时抛出 `ValueError`。即使绕过此校验，`mutagenesis.py:461-468` 也会因 `wt_ascr3 is None` 跳过所有受体。
- **证据**：
  - `wt_singlestage/docking_results.json`：3 条目，全为 ascr18（Bash `cat | python3` 验证）
  - `run_mutagenesis_alanine.py:62-63`：`missing = [k for k in expected if k not in baseline]; if missing: raise ValueError(...)`
  - `mutagenesis.py:463-468`：`if wt_ascr18 is None or wt_ascr3 is None: ... continue`
- **应该怎么说**：#5 无法启动，WT 基线缺少 ascr3 数据。必须先补全。
- **严重度**：**HIGH** — 不修复则 #5 直接崩溃

### [2] 推断冒充事实 — wt_singlestage 基线与当前 PDBQT 一致性

> （隐含假设）wt_singlestage 的 ascr18 值可与 #5 的 ΔG(mut) 直接做差计算 ΔΔG

- **问题**：wt_singlestage GprC_ascr18=-8.235（04-08 产出），multiseed seed=42 的 GprC_ascr18=-8.275（04-09 产出）。差值 0.040 kcal/mol 远超 Vina 同条件噪声（GprC SD=0.009，即 >4σ）。相同 seed/受体/box 应产出确定性结果。差异说明两次运行使用了不同版本的 ascr18 PDBQT。
- **证据**：
  - `wt_singlestage/docking_results.json`：GprC_ascr18 = -8.235
  - `multiseed_stats.json`：GprC_ascr18 values[0]（seed=42）= -8.275
  - config.yaml seed=42（第 124 行），multiseed seeds 第一个也是 42
- **应该怎么说**：如果重跑 WT 基线，应使用当前 Windows 上的 ascr18 PDBQT，确保与 #5 alanine scan 使用同一配体文件。不可直接沿用旧 wt_singlestage JSON 的 ascr18 值。
- **严重度**：**HIGH** — 基线不一致会导致 ΔΔG 有 ~0.04 系统偏差

### [3] 推断冒充事实 — ascr3 未受 freeze_terminal_torsions bug 影响

> ascr3 大概率 DOF ≤11，因此 freeze_terminal_torsions 不会被调用

- **问题**：这是合理推断（ascr3 碳链短于 ascr18），但配体 PDBQT 仅在 Windows 上，无法从 Mac 验证 DOF 数量。`prepare_ligand.py:291` 的触发条件是 `dof_count > max_dofs`（max_dofs=11），ascr3 的实际 DOF 未确认。
- **证据**：本地无 `ascr3_optimized.pdbqt`（`ls prepared/ligands/` 为空）
- **应该怎么说**：ascr3 可能未受影响（碳链较短），但需在 Windows 上运行 `count_dofs(ascr3_optimized.pdbqt)` 确认。
- **严重度**：**MEDIUM** — 推断方向大概率正确，但未经验证

### [4] 缺少指针 — run_wt_singlestage.py 覆写行为

> （未在之前讨论中明确提出）wt_singlestage JSON 会被覆写

- **问题**：`run_wt_singlestage.py:142-146` 将完整 results 列表写入 JSON，不合并旧数据。如果尝试 `--ligands ascr3` 仅补跑 ascr3，已有的 ascr18 数据会丢失。补全基线时必须同时包含 ascr18。
- **证据**：`run_wt_singlestage.py:142-146`：`out_json.write_text(json.dumps([asdict(r) for r in results], ...))` — 完整覆写
- **应该怎么说**：补跑时必须 `--ligands ascr18 ascr3 ascr7`，不可仅跑 ascr3。
- **严重度**：**MEDIUM** — 操作失误会丢失数据，但可重跑恢复
