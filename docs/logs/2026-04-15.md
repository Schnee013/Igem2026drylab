## §1 学员复现 ImportError 修复

### 问题

学员运行 `run_wt_singlestage.py` 时报错：

```
ImportError: cannot import name 'get_results_subdir' from 'utils'
(.../src/modeling/docking/utils.py)
```

Python 找到了 `docking/utils.py` 而非 `docking-repro/utils.py`。

### 根因

所有 `docking-repro` 脚本的 `sys.path` 配置为两次 `insert(0, ...)`：

```python
sys.path.insert(0, str(_this_dir.parent / "docking"))  # 先插 docking/
sys.path.insert(0, str(_this_dir))                     # 再插 docking-repro/
```

逻辑上 `docking-repro/` 最终在 index 0（正确），但依赖插入顺序，脆弱易错。学员若拉取旧版本（顺序写反时）即复现。

### 修复

**弃用 `docking/` 整体**（见 §2），直接从根源消除歧义。所有 `run_*.py` + `dock.py` 的 `sys.path` 改为：

```python
sys.path.insert(0, str(_this_dir))   # 仅 docking-repro/，不再引用 docking/
```

涉及文件（9 个）：`run_wt_singlestage.py`、`run_wt_twostage.py`、`run_multiseed.py`、`run_saturation_gpr2.py`、`run_mutagenesis_saturation.py`、`run_gprc_expanded_box.py`、`run_mutagenesis_alanine.py`、`generate_mutant_fastas.py`、`dock.py`。

## §3 ProLIF 盐桥检测修复（Anionic/Cationic 电荷注入）

### 背景

PDBQT 格式不编码形式电荷，OpenBabel PDBQT→SDF 输出中 ARG 胍基无 +1、配体羧酸无 -1，导致 ProLIF Anionic/Cationic SMARTS 匹配永远为空（2026-04-14 确认根因）。

### 修改文件

| 文件 | 改动 |
|------|------|
| `src/modeling/docking-repro/config.yaml` | 每个配体新增 `smiles_pH74`（COO⁻ 去质子 SMILES） |
| `src/modeling/docking-repro/run_ifp_analysis.py` | `fix_sdf_valence()` 加 `template_smiles` 参数；新增 `fix_receptor_charges()`（ARG +1 / ASP-GLU -1）；`analyze_pair()` 串联两个修复；`main()` 从 config 读 `smiles_pH74` |
| `src/modeling/docking-repro/run_ifp_mutants.py` | 透传 `template_smiles` 到 `analyze_pair()` |

### 验证结果

- WT GprC IFP 重跑：`Anionic=12 hits`（修复前=0），ARG395.A=`Anionic=4`（Hu2024 R6.45 阳性对照）
- V138R + ascr18：`ARG138.A: Anionic=2, Hydrophobic=3, VdWContact=9`（ascr3 ARG138 未进 Top-10）
- `mutant_contacts.csv` interaction 列含 Anionic ✓，其他 13 种类型无显著回归 ✓

### 结论层

此修复检验"现有 docking pose 中是否存在盐桥几何"，不能检验"盐桥是否热力学驱动结合"（Vina 无静电项）。阳性检出为探索性支持证据，热力学确定性待 MD。
