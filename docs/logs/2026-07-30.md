## 18/20 成因审计与 v4 CPU 合同校正

- Vina v1.2.6 官方 CLI/源码将 `num_modes` 定义为最大输出数。搜索结果经 RMSD
  去重，输出另受 `energy_range` 上限控制，因此正常返回少于 20 个 mode
  不等于计算崩溃。
- 三个 18-mode attempt 均有完整 Vina 结果表、连续 `MODEL 1..18` 和可解析
  affinity。`dock.py::_run_vina()` 仅在 return code 0 且 affinity 非空时返回；
  实际异常来自 `docking_manifest.pose_evidence()` 的
  `actual_modes == expected_modes` 强制检查。因此 v4 的
  `technical_failure` 是旧项目合同产生的终态，不是 Vina crash。
- R167Y-ascr18 两次 best/last affinity 为 -6.953/-5.835，跨度
  1.118 kcal/mol；R167Y-ascr3 为 -7.097/-5.905，跨度
  1.192 kcal/mol，均小于 `energy_range=3.0`。提高 energy range 不能解释或修复
  当前 18-mode 输出。
- R167Y-ascr18 在 v3 CPU8、v4 attempt 1 和 v4 attempt 2 的 pose SHA256 均为
  `1ac5be6c79be7bd85b6bf1f5cd33c7ef440dd61eac3a16152b0d394999e23e69`；
  v3/v4 共通的其他六个 job 也逐一 byte-identical。固定输入、seed 和算法下继续
