## 一、核心思路

Skill 本质就是一个 Markdown 文件（SKILL.md），放在项目的 `.claude/` 目录下。每次你在项目里启动 `claude` 时，它会自动加载这个文件，知道：

- 你的项目是什么、当前进展到哪
- 代码在哪、数据在哪、实验结果在哪
- 最近的工作日志记录了什么

这样你不用每次重复背景，Claude Code 读完索引文件就能直接干活。

---

## 二、推荐工具链

### 源码管理 → GitHub

你已经在用了，不用变。建议仓库设为私有，README 里写清楚项目概述。

### 开发平台 → 服务器 + 本地双端

|场景|在哪跑 Claude Code|典型操作|
|---|---|---|
|写/改代码|本地或服务器都行|改模型结构、写数据处理 pipeline|
|跑训练/实验|服务器|提交训练任务、监控 GPU|
|看日志分析结果|服务器（数据在那边）|分析 wandb/tensorboard 日志、画图|
|写论文/文档|本地|写 LaTeX、整理实验表格|

### 实验追踪 → Weights & Biases (wandb)

记录训练指标（loss、学习率、GPU 占用等）。wandb 是机器指标，你的 Skill 系统记的是人的思考和决策。

### 工作日志 → Markdown + Git

这是整套系统的关键。日志文件跟代码一起放在仓库里，Claude Code 能直接读，git 提供版本记录。

## 四、核心文件模板

### 4.1 SKILL.md（放在 `.claude/SKILL.md`）

```markdown
---
name: bio-llm-research
description: 生信大模型科研项目管理。管理代码开发、实验运行、日志记录和论文写作的完整工作流。
---

# 生信大模型研究项目

## 启动流程

每次对话开始时，先读取项目索引文件了解当前状态：

1. 读取 `docs/INDEX.md` — 了解项目全貌、当前阶段、卡点
2. 读取 `docs/logs/` 中最新的日志 — 了解最近做了什么
3. 根据用户需求开始工作

## 关键路径

- 索引文件：`docs/INDEX.md`
- 工作日志：`docs/logs/YYYY-MM-DD.md`
- 源码：`src/`
- 训练配置：`configs/`
- 实验结果：`experiments/`
- 论文文件：`papers/`
- 远程仓库：GitHub（具体地址见 INDEX.md）

## 环境说明

本项目可能在两个环境下使用 Claude Code：
- **服务器端**：有 GPU，用于训练、实验、日志分析
- **本地端**：用于代码开发、论文写作、文档整理

请根据当前环境调整操作建议（例如不要在本地建议跑训练）。

## 工作规范

### 写代码时
- 遵循项目已有的代码风格
- 重要改动先说思路，确认后再动手
- 改完代码后提醒我更新日志

### 跑实验时
- 检查 configs/ 下的配置文件
- 建议使用 `experiments/exp-XXX-描述/` 的命名格式
- 实验结束后帮我整理结果到日志

### 分析结果时
- 先读最近的实验日志了解背景
- 结合 INDEX.md 中的研究问题来解读结果

### 写论文时
- 读取 INDEX.md 了解论文进度
- 参考 experiments/ 中的数据
- 引用格式遵循目标期刊要求

### 更新日志
- 每次完成重要工作后，提醒我更新 `docs/logs/` 中的当日日志
- 同步更新 `docs/INDEX.md` 的"最近进展"部分
```

## 五、日常使用方式

### 场景 1：在服务器上开发 + 跑实验

```bash
# SSH 到服务器
ssh gpu-server

# 进入项目目录，启动 Claude Code
cd ~/bio-llm
claude
```

Claude Code 自动加载 `.claude/SKILL.md`，读 INDEX.md，然后你就可以直接说：

> "帮我看看上次实验的结果，分析一下 loss 为什么在第 50 个 epoch 后不降了"

> "改一下 data loader，加上对 UniProt 数据的支持"

> "帮我提交一个新的训练任务，用 configs/exp-003.yaml 的配置"

### 场景 2：在本地写论文/整理文档

```bash
cd ~/bio-llm  # 本地 clone 的仓库
git pull       # 先拉取服务器上的最新改动
claude
```

> "帮我根据 exp-001 和 exp-002 的结果写 Results 部分的初稿"

> "把最近一周的实验日志整理成一个进度汇总"

### 场景 3：结束一天的工作

跟 Claude Code 说：

> "帮我写今天的工作日志，然后更新 INDEX.md"

Claude Code 会根据你们当天的对话内容，自动生成日志并更新索引。

## 六、最佳实践

### 保持索引文件是"活"的

INDEX.md 是整个系统的灵魂。每次结束工作时花 1 分钟更新它，下次启动 Claude Code 时就能无缝衔接。最重要的三个字段：

- **当前阶段**：让 Claude 知道大方向
- **主要卡点**：让 Claude 聚焦在最需要帮助的地方
- **最近进展**：让 Claude 知道上下文

### 日志不用写得很详细

一天的日志写 10-20 行就够了。关键是记录：做了什么、发现了什么、卡在哪。Claude Code 能从这些简短的记录中推断出大量上下文。

### 用 Git 同步两端

在服务器上做完工作后 `git push`，本地 `git pull`，保证两端的 INDEX.md 和日志始终一致。可以在 `.gitignore` 里排除大型数据文件和模型权重，只同步代码、配置和文档。

### 技术决策单独记录

遇到"用 A 还是 B"这类关键选择时，写一个 decision 文档。未来回顾或写论文时这些极有价值，Claude Code 也能参考这些决策来给出更一致的建议。

## 七、快速上手清单

1. 在项目根目录创建 `.claude/SKILL.md`（复制上面的模板）
2. 创建 `docs/INDEX.md`（填入你的项目信息）
3. 创建 `docs/logs/` 目录，写第一篇日志
4. 把这些文件 commit 并 push 到 GitHub
5. 在服务器和本地分别 `cd` 到项目目录，启动 `claude`
6. 试着说一句："读一下项目索引，告诉我当前的状态"

完成。从此每次启动 Claude Code，它都知道你是谁、在做什么、做到哪了。
